## 阶段与边界

1. 修复服务端增量同步：新增服务端单调游标，保留 since 兼容；事务性升级旧数据库；修复时间精度比较、外键与 push 原子性。
2. 更新 Android / Windows：首次使用新协议全量获取；按上传快照版本确认队列；切换服务端重置游标；Windows 补齐自动同步。
3. 核实 component-hub 源码与公开立创商品查询，形成有源码依据的功能比较；本阶段不直接复制其实现。
4. Android 从包装二维码提取 C 编号，直接查询公开商品信息，严格验证商品编号，保留缓存、离线录入和用户修改优先。查询失败不得伪造商品名称或替换用户库存数量。
5. 运行针对性回归测试、可用的客户端编译验证，并同步 README、架构和集成文档。

## 新同步契约

- GET /sync/pull?cursor=N，N 为非负整数，cursor 优先于 since。
- 响应 sync_cursor=M，与返回实体来自同一数据库快照。
- 首次 cursor=0；成功应用数据后保存 M。旧服务端缺少此字段时采取全量读取兼容策略。
- 客户端 updated_at 继续决定 LWW 冲突；服务端 revision 决定增量发现，两者职责分离。

## 验证与回退
