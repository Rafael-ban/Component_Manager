# Android M1 日常与批量标签打印

本页区分已实现功能和设备验证，避免将汉码的菜单等同本项目已经支持的功能。
参考为用户提供的汉码 3.3.4、M1 对照通信及独立实现；不包含厂商源代码、APK 或二进制。

| 功能 | 本项目方式 | 验证边界 |
| --- | --- | --- |
| 单个元件标签 | 元件标签预览 → 蓝牙打印 | 真实库存快照，打印不改库存 |
| 多元件与份数 | 库存 → 批量蓝牙打印；各元件 1–99 份，一次最多 500 张 | 按元件与份数顺序逐张发送；长批量需实机 |
| 短码、完整码、文字 | 沿用现有 QR 载荷编码和文字字段规则 | 独立 203 dpi 纸面布局，与 PNG/PDF 模板尺寸分开 |
| 预览、尺寸、方向、偏移 | 预览和发送使用相同纸面位图，默认 40×60 mm | 二维码整数像素模块与完整静区；不允许裁掉二维码来适配小纸 |
| 暂停、停止、恢复 | 暂停在当前张结束后生效；立即停止可能留下需要核对的当前张 | 已发送或部分发送不自动重打；重启需要人工核对发送中项 |
| 打印机选择与诊断 | 已配对 Classic/dual M1，逐张核对型号和状态 | 复用 dev.6 通过的分帧、正常标签结束命令与前台连接 |
| 浓度、速度 | 尚未开放写入 | 静态资料有接口，但当前 M1 没有设置效果的实测验收 |
| 纸型、定位、纸张学习 | 尚未开放写入 | 不把不同 SDK 的参数映射混用，不自动重置当前正常设备 |
| Windows、其他品牌 | 后续独立适配 | 本轮不宣称通用 ESC/POS 或其他品牌兼容 |

## 操作流程

实际元件标签不打印外围边框。诊断用的固定测试图仍有边框，用于观察裁切和位置；
二维码周围的白色静区属于可扫描性要求，不是打印边框。

1. 在 Android 系统蓝牙设置配对 M1，打开打印机并装好正确的间隙标签纸。
2. 单个元件从“生成标签”的预览打开“蓝牙打印”；多个元件从库存打开“批量蓝牙打印”。
3. 勾选元件、填写各自份数，选短二维码、完整二维码或文字，填写实际纸宽和走纸长度。
   纸张宽度为打印头方向，纸张高度为走纸方向。首次先用已验证的 40×60 mm、旋转 0、偏移 0。
4. 检查预览，创建队列，再刷新已配对设备并选择 M1。队列保存了当时的标签内容，
   后续库存变化不会改变这次任务；更换纸张或内容请明确清除队列并新建。
5. 开始后保持页面在前台。每张只发一幅图和一次正常标签结束命令，不以多发走纸解决缺图。
6. “已发送”仅代表协议数据和处理通知符合预期，需要检查实物；不能据此推算库存消耗。
   缺纸、开盖、连接失败或处理通知缺失时停止后续项，按界面核对、重打或跳过，再继续。

## 中断与数据

发送前会同步保存 `Sending` 检查点。队列在应用私有目录 `label-print-queue.json`，使用
AtomicFile 原子替换；发送中退出后恢复成“待核对”，不会自动发送该张。
只有一份当前任务；新任务通过显式清除替换，不积累不可清理的历史。
队列包含标签内容快照，留在本机，不加入可分享的蓝牙诊断报告。
保存失败时不继续发送；损坏文件需要明确清除，仅清理打印任务，不清理库存。

## 汉码流程证据

汉码的业务入口接受单标签份数或标签列表和各自份数。M1 路径逐份检查停止标志及状态、
发送一幅位图和一个结束命令，再读取回复。停止主要阻止后续未发送项，并不能撤回已写出的数据；
其返回值也不能证明标签实物完整。本项目以队列核对替代含糊的“全部打印成功”。
协议和 dev.6 两张固定测试的实测边界见 [M1 分析](m1-apk-analysis.md)。

## 0.7.4 实机验收

2026-09-25，Android 15、汉印 M1、40×60 mm 间隙纸：无边框完整二维码标签可扫描并对应正确元件；
零偏移时轻微偏左，该测试设备水平偏移设为 `+0.5 mm` 后接近居中。随后同一元件自动连续两份，
用户确认两张均完整、位置一致、没有额外空白纸。`+0.5 mm` 是此次设备/纸张校准，默认仍为 `0`。
正水平偏移向右，负值向左；设置保存在当前打印任务中，新建任务保留上次纸张设置。

实机还通过预览尺寸/偏移切换、页面返回后恢复待打印队列；没有修改库存。
CI 覆盖不同元件的队列顺序、恢复状态、二维码渲染与可解码性。长批量、不同纸张、
物理缺纸/开盖及发送途中停止后的出纸状态未在本轮逐项实测，仍需按实际设备核对。
