# 蓝牙标签打印完善计划

## 已有基线

M1 / Android 15 / 40×60 mm 间隙纸的 Dev.6 连续两张固定测试已通过。
现有 POLI/LZO、1024 字节原始分帧预算、正常标签结束命令及异步通知解析保持复用。
此验证不等于所有纸张、日常元件标签、长批量或其他品牌已通过。

## 本轮实现

1. **日常标签与渲染**：从元件标签预览进入蓝牙打印，复用已有 QR 载荷与文本模板；
   203 dpi 生成实际纸面位图，预览尺寸、旋转、偏移及内容适配，保留 PNG/PDF 导出。
2. **批量队列**：选择多个元件、各自份数，确认总张数；逐张发送、显示当前项和进度。
   队列持久化，支持暂停、停止后核对、跳过不确定项、明确重打及继续未发送项。
   已写出字节的失败项不能当成未打印自动重试；重启后的发送中项需人工核对。
3. **设备入口**：选择已配对的 M1，展示连接/缺纸/开盖等已知状态；设置与诊断独立，
   普通打印固定正常标签走纸。保留高级诊断，不把试验走纸作为生产设置。
4. **验证与交付**：队列状态、序列、取消/恢复与渲染回归，经 GitHub CI 构建，
   开发版实机检查单张真实元件标签、连续多份和多元件队列。

## 结构与变更边界

- 新建打印队列/本地存储/打印位图模块，不迁移库存数据库，不改变库存数量。
- 复用 `BluetoothPrinterDiagnostics` 已验证发送路径，提供普通标签发送入口；
  UI 调度串行队列，不并行写同一打印机。
- 新打印中心使用 Material 3，单页可滚动列表与固定操作区；元件预览和库存入口接入。
- 设置、队列、位图与传输按职责划分，避免复制整套蓝牙代码。
- 原始抓包、厂商 APK、反编译实现与私密设备信息不进入仓库，不捆绑闭源二进制。

## 后续设备功能

参考汉码功能做矩阵核对；本地份数、模板、方向、偏移可独立实现。
浓度、速度、纸型、定位学习/校准、固件等写设备功能必须有 M1 的具体协议与实机证据。
不把其他型号命令通用化，也不把厂商账号、云模板、商城作为库存打印的必需依赖。
Windows 蓝牙直连与其他品牌协议按后续确认范围接入。

## 验收与回退

CI 优先现有 M1 回归及新增队列/渲染测试；不在本地构建 Android。
先验证一张真实元件标签可扫描，再验证小批量；失败时保留报告，不自动重复出纸。
每个独立模块可回退提交；保留已有标签导出、诊断入口和现有用户库存。
开发版发布不改变正式版通道。
