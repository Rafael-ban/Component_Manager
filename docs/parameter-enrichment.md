# 批量补全旧库存参数

这个维护工具用于已有大量元件、但旧版本未保存官方参数的账户。按现有嘉立创 SKU 联网查询，将电气参数和官方描述补回原记录；名称、数量、库位、最低库存与出入库流水保持不变。无需重新入库，也不需要申请立创 OpenAPI。

## 使用步骤

1. 先让手机、Windows 与服务端完成一次同步，并保留当前库存备份。操作期间避免同时编辑同一批元件。
2. 部署包含此工具的 **API 和 Web** 两部分，登录这批库存对应的账户。管理员只处理管理员自己的库存；普通用户使用自己的账户密钥。
3. 管理员在服务端设置中开启 **Web 库存操作**。只读模式可以预览，不能启动补全。
4. 打开 Web 库存页的“补全旧元件参数”，点击“预览候选”。候选是未删除、SKU 符合 `C` 加数字且尚未保存参数行的记录；已有参数行的记录不在本轮自动覆盖范围内。页面展示总数和前 5 个 SKU。
5. 点击“确认补全全部候选”。无需保持手机在线；服务端逐项查询，页面显示已处理、已更新、已跳过、失败数量。
6. 完成后，手机和 Windows 使用同一账户正常同步。成功项作为元件资料更新传回客户端，不新增入出库流水；参数独立显示在支持此功能的客户端基本信息中。

有配置的 OpenAPI 会优先使用，否则查询公开 SKU 商品页。此操作是用户显式发起的联网查询，不依赖全局 `ENABLE_WEB_FALLBACK_RESOLVERS` 开关，也不会修改该开关。商城页面验证或网络故障仍可能导致部分查询失败。

## 失败、取消和恢复

- 网络错误列为失败，可“重试失败及未处理项”；成功项不会回滚，也不会重复增加库存。
- 官方没有精确匹配或没有明确参数时跳过，不从型号编码猜值。
- 查询期间记录发生变化时，该条不覆盖最新记录；核对后可重试。
- 取消在当前查询结束后生效。未处理项保留为可重试范围。
- 刷新页面或启动请求超时后，可以找回当前账户的活动任务。任务记录仅在服务端内存中，服务重启后需重新预览并处理剩余候选，已写入的资料仍然保留。
- 每个账户只保留最近一次完成任务和当前活动任务；收起结果时可清除完成记录，不会删除元件资料。
- 元件同步继续遵循现有时间戳与冲突处理规则；若某台离线设备仍有编辑，先处理其同步冲突后再核对参数。

## 开发版部署

此工具首先随 dev 版源码与 Web 附件提供。开发版不会更新 Docker Hub 的 `latest` / `web-latest`；只拉稳定镜像不会得到本工具。

使用源码 Compose 的部署，在对应 dev 标签源码目录中，以**原有 Compose 项目名**、原 `.env` 和原 `/data` 挂载构建：

```sh
docker compose --project-name <原项目名> -f docker-compose.yml up -d --build
```

`docker-compose.yml` 同时构建 API 和 Web。若此前使用群晖文件夹映射或自行修改过数据卷，先把相同的挂载和端口设置沿用到该部署配置，避免启动到空数据库。此命令不适用于直接拉取 Docker Hub 镜像的 `docker-compose.hub.yml`；稳定镜像需等包含工具的正式版本发布后再升级。
