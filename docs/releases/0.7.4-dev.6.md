# 0.7.4-dev.6 — M1 实机分帧与处理通知解析

本版依据同一手机上汉码 3.3.4 和元件仓库 dev.5 的 HCI 对照修正实现。
汉码连续两次正常，元件仓库短走纸第一张正常、第二张跨标签或多出纸。

- 40×60 mm 测试图按汉码实机的 1 KiB 原始像素预算拆成 20 帧（19×25 行＋5 行），
  保留完整 320×480 点画布，不通过缩小标签或裁掉二维码掩盖问题。
- 正确分离异步 `dithering_finish\0` 处理通知与 `M1` 型号回复，修复 19 字节
  混合回复被误判为型号不匹配的问题。支持跨读取、跨查询的通知片段。
- 报告新增 `raw_frame_budget_bytes` 及各读取阶段的 `processing_events`。
  处理通知不是物理打印验收回执；状态仍显示已发送、需要确认出纸。
- 保留正常标签走纸默认值和两种诊断模式，不写入设备纸型、定位偏移或纸张学习配置。

## 实机验收

使用 40×60 mm 间隙纸、旋转 0、X/Y 偏移 0，在纸张起点已正确就位的条件下，
先选择“正常标签走纸”打印一张；完整且无额外空白纸后，再于同一页面主动打印第二张。
预期报告含 `raw_frame_budget_bytes=1024`、`frames_sent=20`、
`form_feed_commands=1`、`short_feed_commands=0`；处理通知应被独立计数，型号仍为 M1。
如仍跨标签或多走纸，停止并保存报告，不自动重打或继续试猜固定走纸值。

### 2026-09-25 实测结果

GitHub CI 和发布构建成功后，已通过 USB 覆盖安装签名 dev.6（704006），保留库存数据。
用户确认打印机开机、纸张正常装好后，正常标签模式连续主动打印两张，用户分别确认
**两张内容完整、位置正常，第二张起点没有继续下移，没有额外空白纸**。

两份报告均为 `frames_sent=20`、`bytes_sent_confirmed=19603`、
`form_feed_commands=1`、`short_feed_commands=0`；第二次 `connection_reused=true`。
两次 `post_print_model_first=matched`、普通回复 2 字节、
`post_print_model_first_processing_events=1`，未再触发混合回复导致的型号查询重试。

本次通过范围为该台 M1、Android 15、40×60 mm 间隙纸、固定测试图的连续两张。
不外推为其他固件、纸张尺寸、长批量或日常元件标签均已兼容；二维码扫描解码尚未单独验收。
两种诊断走纸模式未作为正常模式验收。CI 和处理通知均不能替代物理出纸确认。
完整证据边界见 [M1 分析](../m1-apk-analysis.md)。
