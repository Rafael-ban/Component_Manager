# 0.7.4-dev.4 — M1 右对齐修复与多走纸对照测试

Dev.3 实机已能再次出纸，但用户确认在 40×60 mm 间隙标签纸上偏左，
第二次仍可能多出约两张空白纸；同一纸卷在汉码中正常。
本版修复已找到的对齐差异，并提供多走纸对照。**尚未确认多走纸已经修复。**

- 按汉码 M1 的 `loading_position=2` 配置及实际打印链，将默认对齐从
  `ESC a 1`（居中）改为 `ESC a 2`（右对齐）。保留实际纸张宽度，不补成整个打印头宽度。
- 打印后型号查询若收到混合或迟到回复，先短暂收取剩余数据，再至多执行一次只读查询。
  仍严格匹配完整 M1，不从任意回复中寻找子串，不重发图像或走纸命令。
- 所有打印数据写完后，型号回复不明确只记为“已发送，未确认”，并释放连接等待下次确认；
  只有实际连接 I/O 失败才报告连接异常，避免将 19 字节未知回复直接等同于断连。
- 测试打印确认中新增“只发送图像，不追加走纸（诊断）”。默认关闭，每次重新打开确认时重置。
  此模式仅省略末尾的一次走纸命令，纸张可能停留在机内，不是正常打印模式。
  报告记录 `feed_mode` 和实际完成写入的 `form_feed_commands`，用于区分额外走纸发生在哪个阶段。

正常模式仍使用上游 `setPollForm(960)` 对应命令；没有把 960 猜成固定距离后擅自缩短，
也没有写入设备纸型、纸张学习或恢复出厂配置。按本轮范围，不调整上下偏移。

## 复测

1. 安装 Dev.4，关闭汉码，保持同一卷 40×60 mm 间隙标签纸。
2. “纸张与位置”设宽 40、高 60、旋转 0、X/Y 偏移 0。检查修正后的左右位置。
3. 正常模式主动打印一次，等待走纸停止并保存报告；若需复现第二次问题，再主动打印一次。
4. 勾选“只发送图像，不追加走纸（诊断）”进行一次对照，保存报告并记录还会不会多出空白纸。
   不自动重复，不在走纸过程中拉扯或回塞纸张；需要恢复纸张位置时按打印机正常装纸操作处理。
5. 如果只有正常模式多走纸，下一步对比汉码的实际末尾命令和设备参数；如果对照模式仍多走纸，
   继续检查图像传输/设备处理阶段。两种结果都不能仅凭本地写入成功判断机械打印完成。

若对照仍不能定位，可依照 [HCI 取证步骤](../m1-protocol-capture.md) 记录汉码与本应用各两次
固定测试标签的通信。无需清空应用数据或修改已经能让汉码正常打印的设备配置。
