# 0.7.4-dev.5 — M1 短走纸对照

Dev.4 用户在 40×60 mm 间隙纸上连续测试两次“不追加走纸”：两次均写完七帧，
第二次复用了连接，不再多出空白纸，但底部边框、二维码或文字仍有缺失。
因此不追加走纸只能用于对照，不能直接作为正式修复。

- 打印确认增加第三种模式 **“短走纸（试验）”**，采用汉码 SDK 已有的
  `setPrintFeed(90)` 命令 `1B 1B 01 5A 00`。
- 三种模式只改变图像末尾的走纸命令：正常模式一次标签走纸，不追加模式无末尾走纸，
  短走纸模式只发送一次短走纸。仍发送相同的完整 320×480 七帧图像，不裁掉底部内容。
- 每次打开确认时默认选正常模式，不保存试验选择。短走纸不自动追加标签走纸、不自动重打。
- 报告增加 `short_feed_commands`，只计算完整写入的短走纸指令；
  `form_feed_commands` 仍只计算标签走纸。新增三种序列和指令字节回归。

这是试验性对照，**尚未验证它能在 M1 间隙标签纸上完整打印并连续正确定位**。
上游在非标签分支使用此短走纸调用；不能把参数 90 当作已确认的毫米或点数，
也没有据此修改默认标签模式、设备纸型、纸张学习或偏移配置。

## 本次复测

1. 保持纸张宽 40、高 60 mm，旋转和 X/Y 偏移为 0。
2. 在“打印一张 M1 测试标签”的确认弹窗中选 **短走纸（试验）**，打印一次。
3. 观察底部边框和二维码是否完整、是否又多出空白纸。如果第一张仍异常，先停止并保存报告。
4. 第一张正常后，再在同一页面主动打印第二次；需要重新选择短走纸模式。
5. 回传两次报告及底部完整性、空白纸数量。预期报告包含
   `feed_mode=short`、`frames_sent=7`、`form_feed_commands=0`、`short_feed_commands=1`。

写入完成仍只代表已发送，不能证明机械打印完成。若短走纸仍缺内容或多走纸，
下一步应采集汉码的实际通信作对比，按 [HCI 指南](../m1-protocol-capture.md) 操作；
不继续凭猜测调整固定走纸值。
