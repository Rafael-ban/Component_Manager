# 项目 BOM 出库与 component-hub 迁移

本阶段覆盖 Windows WinUI 和 Android Compose。两端使用本地 SQLite，导入和
扣库不依赖服务器；已有同步功能继续同步元器件和库存流水。

## 项目 BOM

1. 打开“项目 BOM”，选择 CSV 或 XLSX。旧版 `.xls` 请先另存为 `.xlsx` 或 UTF-8 CSV。
2. 选择工作表，填写项目名称和生产套数，生成预览。
3. 核对料号、需求量、现有库存和匹配结果；歧义项需要人工选择。
4. 确认出库。缺料、无效数量、未匹配项或预览后库存发生变化时，整批操作不写入。
5. 同一批次重试不会再次扣库。再次生产需要显式新建生产批次，并重新预览。

数量列常见名称为 `Quantity`、`Qty`、`数量`、`用量`。SKU 列可使用 `SKU`、
`Supplier Part`、`LCSC Part #`、`立创编号`、`物料编号`；厂商型号列使用
`Manufacturer Part`、`MPN`、`型号`，配合 `Package`、`Footprint`、`封装`。
首版按常见表头自动识别，不提供任意列映射编辑器。

数量必须是正整数，表示单套用量。总需求为单套用量乘生产套数。同一元器件
通过不同源行或不同匹配方式命中时，先按本地 component ID 汇总，再计算缺料。
明确 SKU 优先；型号与封装必须精确匹配。候选不能绕过用户确认变成替代料。
预览只读，扣库确认会在单个事务内重新核对库存和版本，再写入元器件、出库流水、
同步队列和批次标记，任何一步失败都回滚。

文件限制为 10 MiB、最多 5000 行；XLSX 另有解压大小与列索引限制。
CSV 支持引号、转义引号和引号内换行。XLSX 不执行公式，也不使用公式的缓存值
作为库存依据；含公式的相关表格应先复制并粘贴为值。

批次幂等记录目前只存于提交设备，不随同步传输；它防止本设备重复点击和重试，
不能阻止用户在另一台离线设备上重新导入同一 BOM 并创建新批次。现有同步仍为
元器件快照 LWW，多设备离线同时扣同一元器件不能等同于服务端集中领料。
同一生产批次应由一台设备确认，随后同步。

## component-hub 数据迁移

从 component-hub 导出 JSON 备份，或复制其服务端 `data/components.json`，
在 Android“项目 BOM”选择 JSON，或 Windows 库存页的 JSON 迁移入口打开。
兼容根结构为 `{ "components": [...] }`，可以包含 `version`、`exportDate`
或 `updatedAt`；不把任意根数组当作正式备份。

| 来源字段 | 本项目字段或保留方式 |
| --- | --- |
| `productCode` | SKU；空值生成稳定的 `CH-...` 备用编号 |
| `name` | 元器件名称 |
| `stock`、`threshold` | 当前数量、低库存阈值；必须为非负整数 |
| `encapStandard` | 封装 |
| `location` | 仓位 |
| 中文分类、`category`、`subCategory` | 优先保留中文分类；常见英文 slug 转为中文，原值留存 |
| `model`、`brand`、`notes`、`params` 等 | 结构化备注，保留来源信息 |
| `image` | 可信官方 HTTPS 图片使用“商品图片：URL”备注；其余来源信息不主动下载 |
| `id` | 来源标识；本地创建新 ID |

源项目允许相同 `productCode` 出现多次，而本项目要求有效 SKU 唯一。因此
默认在预览中报告重复并阻止导入；用户可以明确选择跳过冲突项。不会自动合并
数量，也不会覆盖已有元器件。空值备用编号用于保持无料号记录，不能推断为立创编号。

确认时再次校验冲突，整批创建元器件、正库存对应的初始入库流水和同步队列。
导入文件指纹防止同一设备误导入同一文件；修改后的备份仍会经过 SKU 冲突检查。
原项目的全部历史流水、浏览器偏好、MQTT 配置以及自定义分类配置不在组件 JSON
迁移范围内。迁移前建议保留原备份文件；应用不会修改它。

## 商品图片、分类与识别

两端可以从 C 编号直接读取官方 LCSC 国际商城的公开 Product JSON-LD，必须
核对完整 SKU 后才接受信息。商品图片显示在库存列表右侧，缺失或失败显示占位。
Android 使用有界内存/磁盘图片缓存；Windows 的懒查询只更新 UI 缓存，不会因
浏览列表而重写库存。图片地址仅接受已核实的官方 HTTPS 主机，禁止跟随任意地址。
显式录入或编辑时，商品图地址写入“商品图片：URL”备注，沿用现有同步字段。

优先采用官方分类，保留原始“官方分类路径”；已知英文目录提供中文显示，未知
目录保留原文。用户在表单手动修改的内容优先。中文版商城有独立的数值商品 ID，
不能将 `C70565` 去掉 C 后直接拼国内商品页。国内搜索可能返回验证页，因此提供
国内商城浏览器入口，自动查询暂以已验证的国际商城页面为基础。无需 OpenAPI
密钥或自建识别服务器，但公开页面变化、网络限制和缺少数据都可能导致补全失败。

Android 已移除常规设置中的服务端识别开关，正常导入不再调用服务端识别；
服务端旧接口保留以兼容旧客户端。优先扫描二维码或手输 C 编号，再联网核验；
OCR 作为无二维码包装的补充。OCR 使用 CameraX ImageCapture 照片和传感器旋转
信息，而不是截取 PreviewView；仍使用内置 ML Kit，未内置的 Paddle 选项已隐藏，
旧设置自动回退。照片清晰度、反光和字号仍影响准确率，保存前需要核对字段。

库存流水保存出入库的数量绝对值及变动类型；展示时出库转为负值、入库为正值，
调整保留符号。该修复不改写既有流水，也不会再次扣库存。
