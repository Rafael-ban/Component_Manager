# 账户密钥与独立库存实施计划

## 用户确认的范围

- 初次配置的 `API_TOKEN` 是管理员账户密钥；管理员创建普通账户并分发账户密钥，不开放注册。
- Android、Windows 和 Web 使用相同账户密钥访问同一份库存；不同账户库存隔离。
- 管理员负责账户和服务端配置，但库存页面默认只显示管理员自己的库存。
- 普通用户可以使用已有 Web 库存操作，仍受 `WEB_INVENTORY_ENABLED` 开关控制。
- Web 设置与登录页支持跟随浏览器、简体中文和 English，独立 `/setup` 页也支持切换。

## 数据与认证方案

当前 `DATABASE_PATH` 不移动、不重建，继续保存管理员原有库存。新增账户注册表和服务器身份记录；普通账户的数据文件位于同一持久目录的 `users/` 下，文件名由服务端生成的账户 ID 决定。

选择独立 SQLite 而非在所有库存表增加 `owner_id`：现有元件 ID、SKU 唯一约束、库位、分仓库存、变动、墓碑、同步版本与幂等记录均按数据库定义。账户级数据库能复用这些约束，同时避免查询漏加用户过滤条件。账户密钥只用于解析身份；客户端不能指定数据文件路径。

普通账户密钥随机生成，服务端保存摘要。创建和重置时显示一次完整密钥；遗失后由管理员重置。停用账户使密钥失效但保留库存，不提供直接删除数据操作。管理员既有配置文件与环境变量优先级保持不变。

首阶段 MQTT 继续只服务管理员原有库存，普通账户不能修改全局 MQTT 配置，也不能向管理员主题投递库存事件。商品目录等不包含私有库存的缓存可继续共用。

## 接口与客户端约束

- `GET /auth/me`：返回 `server_id`、`account_id`、`name`、`role`；管理员 `account_id` 为 `admin`，普通账户为独立 ID。
- `GET /admin-api/accounts`、`POST /admin-api/accounts`：管理员列出或创建账户。
- `PATCH /admin-api/accounts/{id}`：修改名称或启停；`POST /admin-api/accounts/{id}/rotate-key`：重置密钥。
- `/setup/config`、`/setup/logs`、账户管理及全局 MQTT 设置仅管理员可访问。
- `/sync/push`、`/sync/pull` 根据已认证账户选择数据库。普通账户须携带与身份一致的 `X-Component-Vault-Account-Id`，缺失时提示升级客户端；管理员旧客户端保持兼容。

原生客户端当前每个安装只有一份本地库存。第一阶段给该本地工作区绑定服务器和账户身份，上传前验证；身份不一致时不上传、不拉取、不清空数据，提示更换到独立工作区。同一账户换密钥或在内外网地址间切换允许继续同步。已有成功同步历史但尚无身份绑定的旧工作区只允许首次绑定管理员，避免旧管理员库存被上传到新普通账户。完整多工作区切换 UI 不在此次范围内。

## 分步交付与验证

1. **界面语言**：集中 Web 文案和本地语言偏好；验证设置切换立即生效、刷新保留、表单草稿和登录状态不被切换清除。
2. **服务端账户与隔离**：认证上下文、账户接口、数据库路由及管理员权限。测试两个用户使用相同 SKU/记录 ID 时各自独立，跨账户读取/修改不可见，游标和幂等回执隔离，停用与密钥轮换生效，旧管理员数据保留。
3. **客户端与 Web 接入**：原生同步前身份校验、Web 角色与账户管理入口。测试身份变化时零上传、密钥轮换和内外网切换、普通用户无法操作管理员入口。
4. **验收与发布**：更新实现与部署文档，运行相关测试、Web 构建和 GitHub CI；发布前核对实际产物与 Docker Hub 标签。保持 `master` 主线。

测试使用独立临时数据库，不访问或迁移部署者生产数据。发布前必须完成数据隔离验收；0.7.4 已发布内容不回写替换。

## 恢复与回退

原管理员库存数据库与现有密钥保持原位置。升级前备份完整 `/data`，包含新增用户数据文件和账户注册信息；不可仅备份管理员库存文件而遗漏 `users/`。旧版本不认识普通账户；回退程序时保留这些文件，不能宣称回退后仍能登录普通账户。涉及本地工作区身份不一致时优先保留数据并给出导出说明，不自动清库。
