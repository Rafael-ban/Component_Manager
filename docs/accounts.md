# 多用户账户与独立库存

本指南适用于包含账户隔离功能的版本。升级时先更新 API 服务和管理 Web，再更新 Android、Windows 客户端；旧服务没有账户身份接口，新客户端会提示先升级服务端。

## 管理员和普通用户有什么区别

首次在 `/setup` 配置的 `API_TOKEN` 是管理员密钥。升级已有部署后，它继续访问原来的库存，不需要重新导入。管理员可以修改部署配置、查看运行日志、管理普通账户和配置 MQTT。

普通账户由管理员创建，不开放公共注册。每个账户有自己的密钥和库存。Android、Windows 和 Web 使用同一个账户密钥时，会访问同一份服务端库存；其他账户看不到这份数据。管理员的库存页面也只显示管理员自己的库存，不汇总所有用户。

## 创建账户并交给用户

1. 用管理员密钥登录管理 Web，打开“设置 → 账户管理”。
2. 填写用户名，点击“创建用户”。用户名不能重复，大小写不同也视为重复。
3. 复制新生成的账户密钥并交给对应用户。完整密钥只在创建或重置时显示，服务端只保存普通账户密钥的摘要。
4. 用户在 Android 或 Windows 的连接设置中填写 API 地址和自己的密钥；也可以直接在 Web 登录页使用这份密钥。
5. 首次同步后，客户端会绑定服务器和账户身份。之后同一账户重置密钥或切换内外网地址，不会变成另一份库存。

这里的邀请方式是管理员分发账户密钥，没有公开注册页或邮件邀请链接。不要把管理员密钥发给所有普通用户。

## 网页上操作库存

普通用户登录后可以查看自己的库存与同步状态，设置页面可以切换语言、查看当前使用的密钥。普通用户看不到部署、日志、账户管理和 MQTT 配置入口。

若需要在网页创建库位、元件以及办理入出库，由管理员在设置中启用“允许已登录的 Web 管理台修改库存”。这个开关默认关闭，对所有账户生效；即使打开，每个账户仍只能操作自己的库存。客户端在下次同步时获取网页上的变更。

## 停用账户或重置密钥

- **停用**：旧密钥立即无法继续认证，库存文件仍保留。需要恢复访问时重新启用。
- **重置密钥**：旧密钥失效，管理员将新密钥交给用户，并更新该用户各台设备上的配置。账户身份和库存不变。
- **改名**：只改变显示名称，不改变账户身份或库存。

目前不提供一键删除账户数据，避免误删库存。

## 现有设备换账户时的限制

每个原生客户端安装目前只有一份本地库存，还没有多账户工作区切换界面。已经绑定账户的设备改填另一账户密钥时，会拒绝同步并保留本地数据，不会把旧账户库存自动上传给新用户。

已经使用旧版本同步过的本地库存，首次升级只能绑定原管理员账户。给新普通用户使用时，应使用独立的客户端数据环境或新设备。确实需要迁移库存时，先做好 Excel 备份，再决定导入到哪个账户；不要通过清除数据来处理普通连接故障。

## Docker 持久化与备份

完整映射并备份 `/data`。原数据库内保存管理员库存、服务器身份和账户注册表；普通用户数据库位于相邻的 `users/` 目录。

只备份原数据库会遗漏普通用户库存；只备份 `users/` 又会遗漏账户与密钥摘要。更换域名或内外网地址时保留整个数据目录，服务器身份才能保持不变。账户数据库丢失时，服务会提示恢复文件，不会自动创建空库掩盖丢失。

当前 MQTT 库存事件只发布管理员库存，普通账户事件不会发送到管理员主题。部署步骤见 [Docker 快速部署](docker-quickstart.md)，技术边界见 [架构说明](architecture.md)。
