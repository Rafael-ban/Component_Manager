## 阶段 A：Windows 连接能力补齐

建议作为下一次小功能更新；如有实际需求，可独立纳入 BOM 缺料 CSV 导出。

1. 配置增加可选备用地址，旧配置缺字段时读取为空，不清空已有 Token、库存或同步状态。
2. 设置页显示首选地址、备用地址和此次使用地址；测试草稿仍不自动保存。
3. 每次同步先探测首选地址，仅在传输失败后尝试备用地址；401/422/409 等业务响应不触发回退。
4. 选中后整次 push/pull 固定同一地址；已发出的写请求失败时，不换地址直接重发。
5. 两个地址必须指向同一服务端和数据库；下次同步重新优先探测首选地址。

文件范围：Windows `Models/SyncConfiguration.cs`、`Services/SyncApiClient.cs`、
`Services/InventoryStore.cs`、`Views/SettingsView.xaml(.cs)` 与对应 CoreTests。
不需要服务端数据库迁移；本地设置必须兼容已有安装。

验收：旧单地址配置、首选成功/断网、备用失败、401 不回退、用户取消、push 中途断网不切站、
下次同步再次优先首选地址。通过 Windows CI、便携 ZIP 启动与一台真实 Windows 设备验证后发布。
可安排为 0.6.1 或下一小版本，最终按更新内容确定。

缺料 CSV 若纳入，只从预览导出 SKU、型号、需求、库存、缺料数，不改库存；
两端覆盖中文、零缺料、未匹配行和 Excel 文本兼容。

## 阶段 B：可选 Web 库存操作

建议作为 0.7.0 级别更新，分后端与 UI 两个可验收步骤。

**后端：** 增加默认关闭的 `WEB_INVENTORY_ENABLED`（拟议名称，目前不可用），
保留现有 API Token 鉴权。首版覆盖新增元件、资料编辑、入库、出库和库位选择，
复用库存约束、sync revision 和 MQTT 事件通路。

每次业务操作使用短事务，数量、库位分配、流水和同步状态一起提交。
库存操作带请求 ID 与预期版本；网络重试不重复扣库，过期表单返回冲突并允许刷新后重试。
资料编辑可以采用版本条件更新和同内容状态收敛；如承诺严格的请求 ID 幂等，
则必须持久化请求语义并拒绝同 ID 不同内容，不能将字段相等判断冒充请求账本。

**界面：** 根据后端能力开关显示操作入口；关闭时维持只读。桌面列表/详情与手机
触摸表单分别适配，库位从实际库存位置选择，显示操作前后数量、处理中、失败重试和冲突刷新。
首版不同时加入 Web BOM、浏览器 OCR、离线写入或多用户权限。

文件范围：`server/app/config.py`、`schemas.py`、`repositories.py`、`admin/api.py`、
新增操作模块；Web `lib/api.ts`、`lib/types.ts`、库存操作组件和库存页。
部署提供可选 Web 容器及 CORS 说明，不能将仅包含 API 的镜像称为完整 Web 系统。

验收：默认禁写、数量非负、SKU 唯一、多库位总量一致、并发版本冲突、重试不重复扣库、
事务失败全部回滚、Android/Windows 拉取可见、库存操作与事件记录一致。
MQTT 使用现有 outbox/QoS 1，不承诺网络消息恰好一次；消费者按事件 ID/revision 去重。
浏览器测试窄屏、桌面、断网重试、输入法和返回行为。

回退：关闭开关停止后续 Web 写入，不撤销已经完成的库存变动。
数据库是否新增请求记录表应在幂等方案确定后决定；需要迁移时先保护已有业务数据。

## 阶段 C：硬件打印与按需增强

汉印 M1 先按已有标签尺寸完成一张可扫描标签的真实打印，再实现设备连接、权限、
断连恢复、打印队列、取消和错误提示。汉码 App 能打印、APK 未加密或设备有蓝牙地址，
都不能证明它兼容 ESC/POS、TSPL 或直接接收 PNG。Windows 蓝牙支持单独评估。

表头映射、旧 XLS 和跨设备 BOM 账本按实际样本和协作需求安排，不捆绑进阶段 A。

## 旧草稿与实机验收边界

本地 `.tmp/deferred-next-version/` 是上一轮收敛时保留的未发布草稿。
Windows 回退算法/测试和 Web 表单可以参考，但必须逐模块移植，不能整体应用旧补丁。
Web 操作草稿依赖 `save_sync_payload(..., manage_transaction=False)`；当前函数没有该参数，
单独复制操作模块会运行失败。旧 Windows 设置页也没有 0.6.0 的标签导出等新增内容。
草稿的资料编辑没有持久化 request_id，不能直接宣称拥有严格的请求幂等保证。

已有功能还需实机验收，不应因此再次全量重做 UI：

- Android：连续扫描、声震、相机/图片导入、输入法、大字号和明暗主题。
- Windows：800/1280 宽度、100%/150%/200% DPI、真实网络环境。
- Web：手机触摸、键盘焦点和完整读屏器流程。

历史发现见 [UI 审计](ui-ux-audit-2026-09-16.md)，修复状态以
[实施报告](ui-consistency-implementation.md) 和当前代码为准。
